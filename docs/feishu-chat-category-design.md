# 飞书群组与单聊分类设计

> CLI 用户身份采集、身份映射、二维码登录与统一存储流程见
> [飞书官方 Lark CLI 用户身份采集接入设计](./feishu-cli-integration-design.md)。

## 1. 目标与使用场景

在现有单租户、内部管理员、低并发场景下，为飞书会话保存明确的会话类型，并把“内部数据”中的原“飞书”分类拆分为：

- 飞书群组：普通群聊、话题群以及迁移前的历史机器人群聊。
- 飞书单聊：个人账号 CLI 后续采集的 `p2p` 会话。

两个模块共用消息、附件、时间筛选、排序、分页和预览逻辑，不建立重复的消息表或附件表。本轮不实现 CLI 登录与抓取，但数据模型和页面必须能够接收后续 CLI 提供的单聊字段。

## 2. 会话类型与字段

规范会话模式：

- `group`：普通群聊。
- `topic`：话题群；在内部数据中归入“飞书群组”。
- `p2p`：单聊；在内部数据中归入“飞书单聊”。
- `unknown`：无法从历史数据确认的类型；为了不隐藏旧数据，在内部数据中暂归“飞书群组”。

`feishu_chats` 新增：

- `chat_mode`：上述规范模式。
- `chat_status`：`normal`、`dissolved`、`dissolved_save` 或 `unknown`。
- `external`：是否为外部联系人或外部群；旧数据允许为空，避免把未知误写成内部会话。
- `owner_id`：群主 ID；无数据时为空字符串。
- `p2p_target_type`：单聊对象类型，例如 `user`。
- `p2p_target_id`：单聊对象稳定 ID。

消息继续通过 `feishu_messages.chat_id` 关联 `feishu_chats`，不增加单聊专用消息表。

## 3. 采集与持久化

- 机器人发现会话时保留飞书返回的 `chat_mode`、`chat_status`、`external`、`owner_id` 和单聊对象字段。
- 机器人接口默认只返回群组；字段缺失时按 `group` 处理，但显式返回的 `topic` 必须保留。
- 任务本地元数据保存会话类型，后续任务状态更新时不能把数据库中的类型覆盖回 `unknown`。
- 历史任务文件没有类型时按 `group` 兼容，因为 CLI 个人采集尚未接入，现有任务均来自机器人链路。
- PostgreSQL upsert 使用非空的新值更新会话资料；`unknown` 不覆盖已经确认的 `p2p/group/topic`。
- 数据库迁移把迁移前已有会话归为 `group`，保证原“飞书”里的数据继续出现在“飞书群组”。

## 4. API

`GET /api/internal/feishu/chats` 增加可选参数：

```text
category=group | p2p
```

- `group` 返回 `chat_mode IN ('group', 'topic', 'unknown')`。
- `p2p` 只返回 `chat_mode = 'p2p'`。
- 参数缺省时保留现有兼容行为，返回全部会话。
- 非法值返回 400，不能静默回退到全部会话。

会话摘要增加会话模式、状态、外部标记和单聊对象字段。消息分页与附件 API 保持不变。

## 5. 页面流程

“内部数据”的数据分类改为两个可点击模块：

1. 飞书群组
   - 显示普通群聊、话题群和兼容历史群聊。
   - 二级列表标题为“群组列表”。
2. 飞书单聊
   - 只显示 `p2p` 会话。
   - 二级列表标题为“单聊列表”。

页面同时加载两个分类的会话摘要，以展示各自数量。切换分类时：

- 清除另一分类的已选会话。
- 默认选择新分类中最近活跃的第一项。
- 页码重置为 1，分页快照清空。
- 日期范围与页内排序保留，方便在两个模块间对比同一时间范围。
- URL 保存 `category`、`chat`、日期、排序、页码和快照；刷新后恢复当前模块。

空状态、加载提示、标题和面包屑必须根据“群组/单聊”分别显示，不能继续统一写成“群组”。

## 6. 兼容与风险

- 同名群聊和单聊始终使用 `chat_id` 区分，名称只用于展示。
- 旧任务 JSON 缺少新字段时在内存中补成机器人群组，不要求人工修改历史文件。
- `external` 旧数据保持未知，不默认写成 `false`。
- `topic` 在存储层保留，但当前产品分类与普通群聊合并。
- 后续 CLI 采集必须传入 `chat_mode=p2p` 和 `p2p_target_id`；若缺失，不允许把单聊伪装成群组。

## 7. 验收标准

1. 数据库迁移可重复执行；既有会话迁移后仍在“飞书群组”。
2. 新机器人任务保存 `group/topic` 及会话状态，不会产生 `p2p` 任务。
3. `category=group` 不返回 `p2p`；`category=p2p` 不返回群组、话题群或未知类型。
4. API 缺省 `category` 时保持旧调用兼容；非法分类返回 400。
5. 内部数据侧栏显示“飞书群组”和“飞书单聊”及各自数量。
6. 切换模块后不会短暂展示上一模块消息，默认选择目标模块最近活跃会话。
7. URL 刷新后恢复分类、会话、日期、排序、页码和快照。
8. 同名群聊和单聊可以分别选择，数据不串联。
9. 两个模块的正文、附件、时间筛选、排序和固定 20 条分页行为一致。
10. 没有单聊数据时展示单聊专用空状态，不影响群组浏览。
11. 历史任务回填仍归入飞书群组，重复回填不增加消息和附件数量。
12. `corepack.cmd pnpm test`、`typecheck`、`build` 和 Python 单元测试全部通过。
13. 启动 Web/API 后，模拟“内部数据 → 飞书群组 → 查看消息 → 飞书单聊 → 空状态或查看单聊 → 刷新恢复”的完整用户流程；失败步骤单独列出。
