# 飞书历史消息采集与时间线 MVP 设计

> 本文保留机器人采集链路的原始 MVP 设计。个人用户身份 CLI 接入请以
> [飞书官方 Lark CLI 用户身份采集接入设计](./feishu-cli-integration-design.md) 为准。

## 目标

在 DLR 数据采集后台提供一条可实际运行的人工采集链路：管理员在页面手动输入飞书 App ID 和 App Secret，验证凭证后选择机器人已加入的群聊，启动 Python 采集任务，并在任务运行期间逐页看到已经采集的群聊时间线。

## 本轮场景与边界

- 单租户、内部管理员、低并发使用。
- 任务只允许人工发起，不做定时任务和事件订阅。
- 页面只展示群聊时间线，不做关键词、成员或时间筛选。
- App Secret 只保存在 API 进程内存中的短期会话，任务结束、会话过期或服务重启后丢失。
- 同一群聊同一时刻只允许一个运行中的任务。
- 当前 Database 和 Storage 包仍是占位实现，本轮使用被 Git 忽略的文件存储完成可运行验收；持久化接口需保持可替换，后续迁移 PostgreSQL 和私有 OSS。
- 本轮不把本地文件附件当作生产公开下载方案；附件只能经 API 的受限路径读取。

## 用户流程

1. 打开“飞书历史采集”页面，输入 App ID 和 App Secret。
2. 点击“验证并获取群聊”。API 通过 Python 桥接任务验证凭证并返回机器人所在群列表。
3. 浏览器立即清空 Secret 输入值，服务端保存一个短期凭证会话。
4. 用户选择一个群聊并点击“开始采集”。
5. API 创建任务目录并启动 Python 子进程；Secret 通过标准输入传递，不进入 URL、进程参数、数据库或日志。
6. Python 按创建时间升序分页读取消息，每完成一页就输出一个 JSON 事件。
7. API 将每页写为独立临时文件并原子替换，再更新任务状态。
8. 前端轮询任务状态和下一段消息游标，逐步追加时间线。
9. 任务成功后清除对应凭证会话；任务失败后保留页令牌，可重新输入凭证后继续。

## 组件设计

### Python 桥接器

位置：`collectors/internal/python/feishu_bridge.py`。

- `chats` 模式：换取 `tenant_access_token`，分页返回机器人所在群。
- `crawl` 模式：获取成员姓名、分页读取消息、解析正文和资源、下载可访问附件、按页输出事件。
- API 基地址可通过环境变量覆盖，用于本地假服务集成测试。
- 网络错误、429 和 5xx 使用有上限的指数退避。
- 每个 JSON 事件占一行，标准错误只输出不含凭证的诊断信息。

### API

- `POST /api/feishu/sessions`：验证凭证并返回短期会话和群列表。
- `POST /api/feishu/jobs`：选择群并创建任务。
- `POST /api/feishu/jobs/:id/resume`：用新凭证会话恢复失败任务。
- `GET /api/feishu/jobs`：任务列表。
- `GET /api/feishu/jobs/:id`：任务状态。
- `GET /api/feishu/jobs/:id/messages?cursor=<offset>&limit=<n>`：增量读取时间线。
- `GET /api/feishu/jobs/:id/attachments/:messageId/:fileName`：读取任务目录内附件。

API 不记录请求体。凭证会话使用随机 ID，默认 30 分钟过期。任务状态为 `queued`、`running`、`completed`、`partial` 或 `failed`。

### 文件持久化

每个任务使用独立目录：

```text
collectors/internal/run-data/feishu/jobs/<job-id>/
├─ job.json
├─ pages/
│  ├─ 000001.json
│  └─ 000002.json
└─ attachments/<message-id>/<file>
```

页文件先写 `.tmp` 再原子替换。任务元数据保存 `chat_id`、群名、页数、消息数、附件统计、下一页令牌和错误，但不保存 App Secret。

### 前端

- 保留 DLR 原数据采集后台为 `/`；飞书采集使用独立路由 `/collectors/feishu`，避免新增功能覆盖项目入口。
- 首页“聊天记录”卡片提供“进入飞书历史采集”按钮，飞书页面提供返回首页入口。
- 凭证卡片：App ID、密码型 App Secret、验证按钮和错误状态。
- 群选择卡片：展示群名与 `chat_id`，必须选中后才能启动。
- 任务进度：状态、页数、消息数、附件成功/失败数量。
- 群聊时间线：按创建时间升序追加，展示发送者、时间、消息正文、类型、回复关系和附件。
- 当前任务 ID 写入 URL 查询参数，刷新页面后可恢复任务和时间线，但不恢复凭证。

### 消息文本去重

- 采集端在扁平化富文本对象时，对来自标题与正文结构的完全相同片段去重；列表内部的重复文本仍按原顺序保留，避免改写用户实际输入。
- 当消息正文与某个附件名称完全一致时，正文不再单独保存，由附件卡片承担文件名展示。
- 前端兼容修复前已经落盘的数据：隐藏与附件名完全相同的正文；仅对带附件的 `post` 富文本消息折叠“前半段与后半段完全相同”的结构性重复。
- 没有正文但存在附件的消息只展示附件，不显示 `[file]`、`[image]` 等占位文本；真正没有正文和附件的消息仍显示类型占位。

## 安全设计

- Secret 不进入查询参数、日志、任务文件、浏览器持久化或子进程参数。
- Python 凭证只通过标准输入接收；标准输出协议禁止回传凭证。
- 附件路径逐段校验并在解析后确认仍位于任务附件根目录。
- 文件名清理 Windows 保留字符和保留名称。
- API 仅允许配置的 Web Origin 跨域访问；生产环境必须使用 HTTPS 和身份认证。

## 验收标准

1. 错误凭证返回可读错误，不能进入群选择。
2. 正确凭证能列出机器人所在群，Secret 随后从浏览器输入状态清空。
3. 未选择群聊不能创建任务。
4. Python 子进程参数和服务日志中不存在 App Secret。
5. 同一群聊同时只能运行一个任务。
6. 每完成一页，任务页数和消息数增加，前端无需等待全部完成即可看到消息。
7. 页面刷新后可通过 URL 中的任务 ID 恢复时间线和任务进度。
8. 时间线包含发送者、时间、正文、类型、回复关系及附件状态。
9. 图片可在页面中预览，其他附件可以通过 API 下载；目录穿越请求被拒绝。
10. Python 或 API 中断后，已落盘页不丢失；重新输入凭证后从最后页令牌继续。
11. 自动化测试覆盖内容解析、资源提取、页级持久化、短期凭证、不重复任务、分页 API 和路径约束。
12. `pnpm typecheck`、`pnpm build` 和 Python 单元测试全部通过。
13. 启动 Web/API 后模拟“输入凭证—选择群—开始采集—观察进度—查看时间线”完整用户流程；没有真实凭证时使用本地假飞书服务。
14. 文件/文件夹消息的名称只在附件卡片展示一次；富文本标题与正文相同时只展示一份，附件预览和下载入口保持可用。
15. `/` 展示原数据采集后台的五个功能卡片；“聊天记录”按钮导航至 `/collectors/feishu`，带 `?job=<id>` 的飞书路由仍可恢复既有时间线。

## 生产化后续项

- 将任务、消息、附件关联迁移到 PostgreSQL，并用唯一键实现跨任务幂等。
- 将附件迁移到私有 OSS，加入 SHA-256、病毒扫描、数据分级和临时签名 URL。
- 引入独立任务队列、Worker 租约、取消、限速和运行指标。
- 为大量历史消息增加数据库游标分页和前端虚拟列表。
